### 1.2 两级用户界面设计思路

**背景说明**：

- 底层操作涉及非常原始和底层的细节（点位、机械臂、电机等）
- 终端用户（如做实验的人员）不需要关心这些细节
- 他们关心的是更上层的动作（如"版位从哪里到哪里"）

**设计方案**：

1. **底层界面**（对内/开发人员）：
   - 显示完整的底层操作细节
   - 开发人员使用
   - 包含点位、电机等原始操作

2. **暴露模块**（对外/终端用户）：
   - 通过触发模块暴露简化的操作
   - 只暴露几个关键参数给外部
   - 例如：版位来源、版位目标、输入框最大值/最小值
   - 更方便开发人员上一层使用

3. **上层界面**（实验流程）：
   - 用户先定义实验（如"分子组装"）
   - 创建后以卡片形式展示
   - 提供删除、编辑、进入流程图等按钮
   - 可以直接运行，不需要关心内部细节

## 二、第二场会议要点

### 2.1 核心问题：运行入口的脱节

**现象描述**：

- 程序那边的启动（动作编辑器内）和仿真界面这边的启动有两个入口
- 对用户来说造成脱节和困惑
- 用户不清楚点了"运行"后到底在哪里运行

**现状分析**：

- 动作编辑器内有保存、发送按钮
- 仿真界面顶部也有播放按钮
- 两个逻辑目前没有统一
- 顶部播放运行的是演示脚本
- 动作编辑器的发送是发送到仿真或真机

### 2.2 工具栏交互现状

**现有按钮**：

- 只读模式：防止随意拖动改动
- 保存：修改完后保存 block 数据
- 发送代码：将 block 转成具体可执行代码
- 自动启动发送：配置自动发送

**用户困惑**：

- 一般用户不知道什么叫"发送"
- 其实质是下载程序到控制器运行
- 需要两步骤：先发送，再点运行

### 2.3 Block 与流程图的关系

**现状**：

- 程序编辑器和流程图是两套独立的东西
- 都可以控制天梭图里的组件
- 都可以控制硬件
- 有些项目之前写了 Blockly，后面又写了流程图
- 实际业务中可能是二选一，但有些复杂项目可能需要两套

**流程图特性**：

- 可以从任意入口开始执行
- 可以暂停
- 可以单步执行
- 可以从中间某节点继续

### 2.4 解决方案讨论

#### 方案一：全局语境配置

**思路**：

- 把"孪生/仿真/真机"配置变成全局配置
- 类似于 IDE 的 build configuration
- 运行时根据当前配置发送到对应目标

**优点**：

- 逻辑统一
- 用户只需关心当前语境

#### 方案二：复选框控制

**思路**：

- 保留播放按钮
- 设置两个勾选项：
  - 勾选1：真机运行（下载程序并运行）
  - 勾选2：仿真环境运行
- 至少勾选一个才能运行
- 如果没有连接真机，相应勾选灰掉

**优点**：

- 明确告诉用户运行目标
- 避免歧义

#### 方案三：参考 IDE 范式

**思路**：

- 参考安卓开发 IDE、小程序开发 IDE
- 概念：Build + Run/Debug
- 发送 = Build（编译生成可执行文件）
- 运行 = Run（选择目标运行）

**具体建议**：

- 发送 + 运行可以合并为一个操作
- 明确区分：Build 是编译，Run 是运行到目标
- 类似 IDE 的 target selector（真机/模拟器）
